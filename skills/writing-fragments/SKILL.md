# Writing Fragments

Collect useful raw writing before choosing structure.

1. Establish the topic, audience, and a destination file. If a file already exists, read it before writing.
2. Interview for concrete claims, examples, scenes, observations, objections, evidence, phrases, and unfinished thoughts. Do not force an outline during this phase.
3. Append useful fragments to one Markdown file. Preserve user edits between turns by rereading before every write.
4. Keep fragments heterogeneous. A fragment can be a sentence, argument, example, quote supplied by the user, code sample, list, anecdote, or unresolved thought.
5. Separate fragments with a horizontal rule. Use one H1 working title and avoid metadata that the user did not request.
6. Distinguish sourced facts from the user's own claims. Do not invent evidence or quotes to make the material feel complete.
7. Allow direct commands such as cut, sharpen, merge, split, or rewrite a named fragment without restructuring the rest.

Completion criterion: the file contains enough concrete material to support later shaping, while structure and ordering remain intentionally undecided.
